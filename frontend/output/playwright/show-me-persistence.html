✦ LESSON ARCHITECTURE · GRADIENT

ObservablePersistence

Distinguish actual persistence from descriptions and previews. When persistence is requested, perform the write and ensure the result is observable by an independent reader. Never substitute returned metadata for a required write — and never modify existing files when only a preview is requested.

1 · REQUEST FLOW

Caller → publish_snapshot(path, data, preview=False)

Return contract: {"path": path, "data": data} — returned after the persistence work, never instead of it.

✕ Before: description as result

return {"path": path, "data": data} with no write. A fresh reader observes nothing. Verifier: FAIL.

✓ After: routed by intent

  • preview=True → return description, filesystem untouched
  • preview=False → boundary checks → real write → fresh-reader verify → return

Independent reader (separate process)

Opens path after return, asserts exact UTF-8 bytes. The only accepted evidence of persistence.
